# VT-739 — the loop runs with its per-node trace silently off

## The defect

`manager/workflow.py::_dispatch_specialist_step` opens
`observability_context(run_id=UUID(task_id))`, but the `pipeline_runs` row it just created via
`_open_dispatch_run(tenant_id, run_id)` is keyed on **`run_id`**, not `task_id`. And
`migrations/006_pipeline_steps.sql:24` is:

```sql
run_id UUID NOT NULL REFERENCES pipeline_runs (id),
```

A `manager_tasks.id` has no `pipeline_runs` row, so **every `state_transition` write from the
langgraph node hook FK-violates**. `observability/langgraph_hooks.py` catches everything and logs
`"state_transition write_step raised; swallowed"`. Net effect: the enforce loop — the path that
runs every delegated turn — has no per-node trace at all, and has not had one for as long as the
loop has existed. Nothing failed, so nothing surfaced.

This is why the VT-738 delegation investigation had to be done by reading transcripts: the rows
that would have said which node ran were never written.

## Why this is NOT a one-token fix (I built it, then reverted it)

The obvious change is `observability_context(run_id=run_id, …)`. It was proposed to me as
record-only. **It is not record-only.** `ctx.run_id` is read as *identity* by everything running
inside that graph:

- `agent/specialist_return.py` (two sites)
- `agents/sales_recovery_executor.py` (four sites — `candidate_build`, `compose_drafts`,
  `persist_batch`, and the `arm()` call)
- `agents/customer_send_choke.py`
- `agent/orchestrator_agent.py`, `agent/orchestrator_agent_driver.py`, `agent/lane_tenant.py`,
  `agent/integration_agent.py`

**Campaigns are created under it.** So repointing `ctx.run_id` silently changes `campaigns.run_id`
— on the money path, and on the exact column the gate's own `assert_route` joins
(`convo_harness.py::_campaign_id_for_run`). A change to what a money-path row is keyed by is a
migration-shaped decision with a backfill question attached, not a logging tweak.

A warning now sits in `workflow.py` next to the mismatch, and
`tests/orchestrator/manager/test_vt738_loop_observability.py` keeps it there — deliberately written
so it does NOT assert the defect is fixed (a permanently-red test is a broken window, not a gate).

## Scope

1. **Decide the identity model, explicitly.** Either (a) the loop's graph keeps the task id as its
   run identity and we give it a real `pipeline_runs` row to satisfy the FK, or (b) the graph moves
   onto the dispatch run and everything keyed by `ctx.run_id` moves with it — including existing
   `campaigns.run_id` values, which is where the backfill lives. **(a) is the smaller change and is
   the default recommendation**; (b) is only right if a dispatch run is genuinely the better
   identity for a campaign, which is a modelling claim nobody has made yet.
2. Whichever is chosen: prove `pipeline_steps` rows actually land for a loop dispatch. The current
   state passes every test precisely because the writes are swallowed.
3. Keep `_manager_review_node`'s §7D join pinned to the task id (already explicit as of VT-738) so
   it does not silently follow whatever the context ends up carrying.

## Boundaries

- **`campaigns.run_id` must not change value silently.** If option (b) is chosen, the migration and
  the backfill are part of this row, not a follow-up — a half-migrated money-path key is worse than
  the dead trace.
- `assert_route` in `convo_harness.py` joins on `campaigns.run_id`. Any change here re-baselines the
  gate; say so explicitly rather than letting the next run's numbers move for an unrelated reason.
- Do not "fix" this by widening the `except` in `langgraph_hooks.py` — the swallow is not the bug.

## Exit gate

(a) A loop dispatch produces `pipeline_steps` rows with `step_kind='state_transition'` for the
nodes it ran, proven on deployed dev. (b) `campaigns.run_id` semantics are stated in the row and,
if changed, migrated with a backfill. (c) The §7D `manager_review` join still resolves. (d) The
VT-738 warning comment and its test are updated or removed as part of the same change — not left
describing a defect that no longer exists.
