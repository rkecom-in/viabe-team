# VT-721 — the rolling 7-day plan

## Why this is a row and not a rewording
Today's §7A plans **monthly + daily**. Fazal's COO definition requires a **rolling 7-day
horizon revised EVERY DAY**, where each revision explicitly factors (i) what actually happened
in the last cycle and (ii) the coming 7 days. That is a different planning object with a
different cadence and a feedback dependency — net-new capability.

## Scope
- A durable 7-day plan artifact per tenant: objectives, sequenced actions, expected outcomes,
  which specialist/tool each is assigned to.
- **Daily revision pass**: read prior-cycle outcomes (VT-514 audit + §7C impact judgments) →
  keep / drop / re-sequence / add → record WHY each change was made (decision + reason, per the
  management mandate).
- Owner-visible on request ("what's the plan this week?") in the owner's language; VTR-visible
  on the console.
- Feeds delegation: each planned action carries the directive + input + objective the Manager
  will hand the specialist (§0.1d).

## Boundaries
Planning is not effect: a plan may schedule an action, but execution still passes the
deterministic gates + Pillar-7 (ARCHITECTURE §0.1.1). Brain-touching → full-pack ×3.
Sequence after / alongside the single-voice program (VT-718/719/720) — Fazal's call; the
asserted-facts ledger matters here too (a plan told to the owner is an assertion).
