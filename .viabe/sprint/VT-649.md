## Why (Fazal STANDING 2026-07-15)
Agents/tools should be independent MODULES on one integration framework — easy to enable/add, and the
enabler for third-party developer tools later. Codex is ON HOLD until this framework lands; then Fazal
decides who implements the Integration (per-source) + Sales-Recovery modules on the contract. Onboarding
stays wired as core capability.

## What landed (additive — 9 new files, 0 edits to live code; nothing rewired)
`apps/team-orchestrator/src/orchestrator/agent_framework/`:
- **capabilities.py** — `AgentRole{PROPOSER, EXECUTOR}` (the two-role split is first-class) + a POSITIVE
  `Capability` enum (codebase only had a deny-list). DESIGN INVARIANT: no capability value means "send
  directly" — the only side-effecting caps are the `REQUEST_*` family, each serviced ONLY by the facade.
  `GATED_CAPABILITIES` = single source of truth for "needs a gate."
- **manifest.py** — `AgentManifest` (frozen): name/version/role/description, positive capabilities,
  prerequisites (REUSES `AgentPrerequisites` verbatim), tools (deny-list validated), optional
  `entitlement_key` slot. `validate()`: a PROPOSER may declare NO gated capability.
- **context.py** — `ModuleContext` generalizes SpecialistHandoff (proposer) + AgentItemContext (executor).
  `for_proposer()` routes tenant through `resolve_lane_tenant` (ambient dispatch wins over model value =
  IDOR guard); `for_executor()` trusts server-derived id. `ModuleResult` adapts to AgentResult /
  ItemExecutionResult. Fail-closed `TenantResolutionError`.
- **gate_facade.py** — THE TRUST BOUNDARY. Capability-scoped from the manifest; `request_customer_send`
  → existing `customer_send.agent_send_draft` (Gate 0..5), `gate_business_action` →
  `business_impact_choke.assert_or_gate_business_action`. Undeclared gated call → `CapabilityNotDeclared`.
  Tenant pinned to the IDOR-resolved value. A module never imports customer_send/twilio/choke directly.
- **registration.py** — `AgentFrameworkRegistry` (SEPARATE from ROSTER + coordinator registry — register
  changes zero live routing). 4-layer validation: manifest structural + positive-capability, REUSED
  `assert_agent_tools_safe` deny-list, role/impl conformance, name uniqueness. `CoordinatorAgentAdapter`
  proves an EXECUTOR module satisfies the coordinator `SpecialistAgent` Protocol (isinstance-asserted).
- **protocols.py** — `ProposerModule` / `ExecutorModule` runtime_checkable Protocols (the 3rd-party seam).
- **reference_plugin.py** — `BusinessContextReader`, a read-only PROPOSER re-expressing tech_lane's read
  through the contract. Proves registration → capability declaration → IDOR-resolved context → proposal,
  and that its empty facade makes `request_customer_send` raise. No live money path touched.

## The third-party contract (what a future Integration-per-source / SR module implements)
```python
class MyModule:
    manifest = AgentManifest(name=..., version=..., role=AgentRole.EXECUTOR,
        capabilities=frozenset({Capability.REQUEST_CUSTOMER_SEND}),
        prerequisites=AgentPrerequisites(agent="my_module", ...), tools=(...))
    def execute(self, ctx: ModuleContext, gate: GateFacade) -> ModuleResult: ...   # or propose() for PROPOSER
register_agent(MyModule())
```
It re-reads PII from RLS itself, arms send/spend ONLY through `gate.request_customer_send` /
`gate.gate_business_action`; it structurally cannot import customer_send/twilio/choke directly.

## Open design questions for Fazal (gate the CUTOVER, not this inert scaffold)
1. **Role granularity** — one manifest with an AgentRole discriminator + role Protocols (propose vs
   execute), or two separate manifest types? SR is genuinely BOTH (proposer + executor) — allow one
   module to declare both roles, or register as two (current design = two)?
2. **Entitlement (₹5000/agent)** — left as an optional un-enforced `entitlement_key` slot; enablement
   stays COMPUTED (onboarding_gate + is_frozen + budget_status). Promote to a first-class enforced
   manifest field, or keep computed + drop the slot?
3. **Cutover ownership + order** — who migrates SR / Integration onto the contract, and in what order?
   (Codex on hold until Fazal's call.)
4. **manifest → activation_registry** — `manifest.as_prerequisites()` exists but the framework does NOT
   mutate the global REGISTRY at import. Confirm the wiring step populates it from manifests (single
   declaration point) vs. keeping the two registries independent.
