## Root cause

The journey turn-brain composed against its OWN private memory (journey.recent_turns) — empty
at start and blind to signup/system/template sends. The welcome and the first question were
drafted by the same model with disjoint contexts → "two different people". Repeated owner
input re-ran the full pipeline (discovery re-kick → duplicate found-online card).

## What shipped

1. **Wire-truth context** — `_merged_recent_history`: journey recent_turns UNIONED with the
   lifetime conversation_log active window (ALL surfaces: signup, system templates, manager,
   journey), deduped, chronological, capped; the brain now composes against what was ACTUALLY
   sent on the wire. Fail-open.
2. **Continuation rule** (turn-brain prompt): ONE CONTINUOUS MANAGER — every YOU: line is
   yours from moments ago; never re-greet/re-introduce/restate; owner-repeated info gets a
   brief acknowledgment, never a re-ask or a re-run.
3. **Typed-twice guard** (deterministic): a NEW sid whose normalized body equals the owner's
   last turn within 3 minutes → brief ack + re-present the pending question; no re-extraction,
   no discovery re-kick, no duplicate card. Older repeats process normally.

## Evidence

5 pins (union incl. welcome visibility, dedup+fail-open, ack-without-reprocess, old-repeat
passthrough, prompt rule). Onboarding sweep 492 green. Sim run-6 proof pending deploy.
