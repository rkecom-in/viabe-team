# VT-711 — O8 Checkpoint C (Codex)

Brief §2. Spec: o8 design v0.2 §6/§8.

## Scope
**Learning loop:** outcome attribution → lesson distillation → scope triage. Tenant-specific →
**L1/L2** tenant memory (RLS). Repeatable aggregate → anonymize + **k≥10** admission (reuse the
VT-225 k-anon mechanism) + per-tenant contribution caps + stability/differencing checks +
quarantine period → **L3** prior candidate. General → candidate registry. No raw tenant story
or uniquely-identifiable scenario becomes a global prior. No agent writes trusted global
knowledge directly.
**Admission machinery:** corpus versioning, O11 A/B harness hooks, card ablation
(counterfactual replay — score with and without the card, reproduce across scenarios),
evaluation records bound to corpus versions.
**Rollout:** modes `off` (default) | `shadow` | `vtr_canary` | `active`, plus the auto-rollback
conditions (money/regulatory/consent incident · cross-tenant evidence exposure · material O11
regression · abnormal hedge/refusal rate · latency/cost ceiling · citation/provenance loss).
Emergency card quarantine is immediate; permanent demotion requires reproduced ablation.

## Exit gate
Privacy + contribution-control + differencing tests pass · admission machinery runnable but
UNRUN (no baseline yet — no corpus version may be marked improved) · every mode wired,
default `off`, nothing serving any tenant. Thresholds/sample sizes/non-inferiority margins:
Fazal approves before first graduation, not now.
