## Gap (all 4 runs)

The activity flow began at the SYNTHETIC "complete setup" kickoff (a system-injected token,
not a user message). The real journey start — Hi → consent card → I agree → welcome — happened
BEFORE the tenant existed, so tenant-keyed conversation_log never saw it.

## What shipped

- **Migration 184**: whatsapp_signup_sessions.transcript jsonb (pre-tenant turns live ON the
  session row → DPDP retention inherited: declined/expired sessions purge WITH transcripts);
  conversation_log.surface CHECK gains 'signup'.
- **Capture** (whatsapp_signup state machine): every pre-tenant turn appended — first-contact
  owner msg, consent card, unclear re-prompts, declined ack, the consent tap, the welcome.
- **Flush**: on tenant creation (created=True only — replay-safe), the transcript copies into
  conversation_log under the new tenant_id with surface='signup' and ORIGINAL timestamps.
- **Flow UI**: signup-surface bubbles get a dashed border + "NOT LOGGED IN" badge.

## Known residual (separate row candidate)

The "complete setup" kickoff line still renders as an owner turn — it's the internal journey
kickoff token, not typed by the user. Re-labeling it as a system event is a small follow-up.

3 dep-less pins (append entry shape, flush writes surface='signup' + original ts, fail-soft);
