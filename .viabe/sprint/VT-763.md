So: **the seam saw a real cohort; the specialist claimed to have no evidence.** The SR agent has `tools=[]`
— its cohort arrives via `context.dormant_cohort` (`context_builder._build_dormant_cohort`). Either that
came up empty on the specialist's context build (a different call from the seam's cohort check), or the
model had the cohort and refused to plan without a "tool result" to cite (its own words).

**And that is exactly the fact I could not read.** The empty-cohort WARNING did not fire for this tenant;
the built-cohort line is INFO, and the deployed log stream carries WARNING+ only; the consent-gate return
was silent. VT-755 scope 4 instrumented the count for precisely this question and it was invisible.

## Ruled out so far

  it dispatched with a real cohort.

## LOCATED — the kept tenant answered it in one look

Tenant `470fea52` (`sr_approved_send_completes_truthfully`, kept, FAIL/FAIL), the new audit row:

```
00:16:44 dormant_cohort_built   built: 3 candidate(s), 3 bundle(s)
00:16:47 spawn                  Spawning sales_recovery_agent
00:17:19 manager_review         needs_owner_input -> ask_owner
00:21:59 dormant_cohort_built   built: 3 candidate(s), 3 bundle(s)     <- attempt 2, same
   STEP campaign_plan_emitted   insufficient_data  category="evidence"
        "No registered tool result, L4 skill-corpus document, or L2 episodic-memory record is
         available to s[upport…]"
```

**The cohort was there. The model refused anyway, and its own words say why.** The SR prompt
(`sales_recovery_v1.md` §Evidence sources) declared `evidence_refs.source_kind` MUST be exactly one of
`tool_call` / `l4_skill_corpus` / `l2_episodic_memory` — "no others are legal". The specialist runs with
`tools=[]`; L4 retrieval fails on every dev tenant (and the corpus is empty anyway); a fresh tenant has no
L2 episodes. So by the enum's own rule the model has NO legal evidence — and the cohort in its input,
which IS the ledger evidence, has no name in that list. When the model reads the enum loosely it cites the
cohort with `[E1]` and the server heals the ref (already labelling it `source_id="context_bundle"` — under
the wrong kind, `l2_episodic_memory`). When it reads the enum strictly it declines. Model sampling decides
which; that is the intermittency, and the hourly clustering is the model's, not ours.

**Not new** — the enum has read this way since VT-501 — but the rate rose in this batch. Two contributors,
neither proven to be the whole delta: the pre-VT-762 flips were the triage truncation (a different
mechanism, proven 8/24 → 0/24), and the post-VT-762 flips are this one at whatever the model's current
strict-reading rate is. Gate (d)'s 18/18 on these six is the outlier under either reading; recorded, not
explained.

## The fix — one honest word, one sentence, one bounded retry

1. `EvidenceSourceKind.CONTEXT_BUNDLE = "context_bundle"` — the source the specialist ALWAYS has. The
   server heal now writes it honestly (it was already `source_id="context_bundle"` under a mislabel).
2. Prompt: `context_bundle` listed FIRST as the primary evidence, with the sentence that removes the
   contradiction — *"a listed dormant cohort is ledger evidence — never return insufficient_data because
   you have no tool result: you have no tools, and the context is the result."*
3. `run_sales_recovery_agent`: when the model returns `insufficient_data` and `context.dormant_cohort` is
   NON-EMPTY, ONE corrective retry naming the contradiction (n eligible customers, the honest kind, cite it).
   Placed BEFORE parse, because insufficient_data parses fine and nothing downstream would ever question
   it. A second refusal STANDS — an honest no is still allowed; this only removes the case where the
   model's own input refutes it. An EMPTY cohort is never retried (that would be fabrication pressure).

Prompt nudges alone have a poor record here (memory: deterministic fixes land, nudges don't); the retry is
the deterministic net, mirroring the VT-596 schema-rejection retry one branch above it.

## Exit gate

(a) ✅ 4 tests: retry fires on a real cohort and names the kind · empty cohort is NOT retried · bounded to
one · prompt carries the sentence. (b) ✅ the six regressed scenarios ×3 on deployed dev: **18/18 clean**, including
`sr_approved_send_completes_truthfully`, which failed 3 of 4 kept runs pre-fix. The
`VT-763: insufficient_data on a N-member cohort` log line fired **twice** across the 18 — the model
still took the strict reading on two runs and the retry recovered both, which is the point: prompt

retry is the net that does not depend on the model reading the new sentence.
