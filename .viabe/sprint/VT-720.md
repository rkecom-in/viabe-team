# VT-720 — S4: route unification

## Why
S2 (choke) and S3 (ledger) make contradictions *detectable and blockable*. S4 removes the
cause: today's parallel reply-producing routes become **input classifiers** that feed ONE
composer, so partial-context surfaces stop generating owner-bound text at all.

## Scope
Convert the reply-producing gates/handlers (consent direct-handlers, paced-flow beats, journey
walker/turn-brain seams, OAuth resume gates, enforce-path replies) into classifiers that emit
STRUCTURED intent + facts; the single composer renders the one voice. The run-6 class defects
(consent decline on "No changes, looks good"; completion-boundary double replies) are fixed
STRUCTURALLY here rather than patch-by-patch.

## Boundaries + sequencing
Deepest brain-touching change of the program: land only after S2 + S3 are live and stable,
with full-pack ×3 per stage and revert-over-repair. Deterministic effect gates unchanged.
Fazal sequences against the launch queue.

### What shipped
`manager/route_classification.py` — the contract. A converted route returns
`{intent, facts_known, facts_pending_confirm, facts_missing, constraints, urgency,
suggested_disposition}`, never `reply_text`. `onboarding/journey_classification.py` derives journey
state ONCE for every converted onboarding seam. The load-bearing distinction is **confirm-vs-gap**:
a queued CONFIRM carries its `draft_value`, so the value is KNOWN and only the owner's yes is
outstanding — collapsing that into "missing" was the fabrication.

Floors kept every veto. Opt-out/DSR still short-circuits before any composition; each rewrite is
re-checked against the invariant that vetoed the original; every converted route keeps an honest
deterministic fallback, so **the guarantee never depends on the LLM — only the voice does.** Each
route's fallback line was REPAIRED, not merely demoted (a demoted template that still lies just
lies less often) — which is what carried classes 1-2 to 3/3 while the composer was dead.

### Three findings the unit tests could not have produced
1. **The composer was dead on dev.** `_invoke_llm` read `resp.content[0].text`; with extended
   thinking on that is a ThinkingBlock, so EVERY converted route silently fell back. Same class as
   the VT-662 empty-beta death. Caught only because classes 1-2 went 3/3 on the *fallback* line and
   the railway logs were read instead of the green being banked.
2. **S4 has a real latency cost.** `_poll_run_status` polls 90s and reports `running` only if the
   workflow never left it — so the `terminal=running` divergence was a genuinely over-budget turn,
   not a sampling race. A 10s bound did not clear it; the cost is structural, because a converted
   route composes AFTER the turn's own work is spent.
3. **Teardown could destroy a measurement.** A late `tm_audit_log` insert raced the tenant DELETE
   and killed runs 2-3 of a scenario whose run 1 had passed.

### The design change finding (2) forced
Layer 3d now **appends instead of replacing**: the Manager's own sentence survives verbatim and the
gate contributes only the outstanding item — the one fact it actually owns. Stronger than rewriting
(we no longer overwrite the Manager's words at all), zero model calls, and it restored
`terminal=completed` 3/3. The rewrite-vs-append branch was REMOVED rather than gated on a
completion-phrase detector: `contains_completion_claim` is the SEND-claim detector, and a new phrase
list is what Fazal's no-lists ruling and VT-656's state-driven design both forbid.

### Not built, deliberately
The design note's 4th conversion (consent/completion seams) has **no measured breaker** in the
current pack. Three conversions, three measured classes. Flagged rather than counted.
