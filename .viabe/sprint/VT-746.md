# VT-746 — an alert that cannot be written is not an alert

## The defect

`alerts/triggers.py` declares `fast_budget_exhausted` in the `TriggerKind` Literal and gives it a
severity in `_SEVERITY_BY_KIND`. **It was never added to `tenant_alerts_trigger_kind_check`**, last
widened by `migrations/172_vt632_reaper_alert_trigger_kinds.sql`.

Proven by execution, not by reading: a real INSERT of that kind against a fully migrated database is
**REJECTED by the CHECK constraint**.

`llm/fast_budget.py` dispatches the trigger inside a fail-soft `except`, so the `CheckViolation` is
swallowed. The row never lands, nothing is logged at warning level, and **nobody is ever paged.**

## Why it matters more than a missing alert

VT-735 exists to stop a tenant silently burning the Fast tier. The budget enforcement itself works —
what does not work is the part that TELLS ANYONE. So the failure mode is: the budget quietly
exhausts, the Manager degrades to a cheaper tier or refuses work, and the first anyone hears of it
is an owner complaining. The tripwire is the whole point of the row and it has never once fired.

This is **byte-for-byte the class migration 172 was written to fix** for the reaper's three kinds:
a trigger kind declared in Python that the database refuses. It recurred because nothing ties the
Literal to the CHECK.

## Scope

1. Additive migration widening `tenant_alerts_trigger_kind_check` to admit `fast_budget_exhausted`.
   **Allocate the number through the allocator.**
2. **Close the class, do not just fix the instance.** A test that asserts every member of the
   `TriggerKind` Literal is accepted by the live CHECK — so the next kind added in Python fails
   loudly at test time instead of silently at 3am. That test is the real deliverable; the migration
   is one line.

## Boundaries

- Additive only. Do not narrow the existing CHECK.
- The dispatch stays fail-soft: an alert failure must never break the caller. This row makes the
  alert *possible*, it does not make it load-bearing.

## Exit gate

(a) A real INSERT of `fast_budget_exhausted` succeeds against a migrated DB. (b) A test enumerates
the `TriggerKind` Literal against the CHECK and fails if any member is unwritable. (c) The
fast-budget path demonstrably produces a `tenant_alerts` row on exhaustion.
